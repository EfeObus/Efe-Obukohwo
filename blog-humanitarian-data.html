Understanding the Challenge

Humanitarian organizations often rely on fragmented data systems. At Humanitarian Outcomes, we were managing multiple databases and Airtable systems that contained information on humanitarian organizations, field operations, and partner engagement. While these systems were powerful, inconsistencies and inefficiencies were slowing down decision-making and reporting.

Some of the key challenges included:

Data Inconsistencies

Duplicate records, missing fields, and outdated information caused reporting errors. A single organization might appear under three different names, making aggregate analysis unreliable.

Inefficient Workflows

Manual processes for collecting, entering, and analyzing data created delays. Team members spent hours each week on data entry that could be automated.

Lack of Actionable Insights

While data existed, it wasn't always in a format that allowed teams or partners to make informed decisions quickly. Raw spreadsheets don't drive action—clear visualizations do.

Our goal was clear: streamline database management, improve data quality, and enable actionable insights that directly impact humanitarian efforts.

Optimizing Databases for Efficiency

One of the first steps I took was auditing the existing Airtable systems. This involved identifying inaccurate, incomplete, or duplicate records and implementing strategies to clean and normalize the data.

The Data Audit Process

1

Record Inventory

Cataloged all existing records across multiple Airtable bases, identifying data sources, field types, and relationships between tables.

2

Duplicate Detection

Developed SQL queries to identify potential duplicates based on fuzzy matching of organization names, addresses, and contact information.

3

Data Normalization

Standardized field formats across all records—consistent date formats, standardized country names, and unified categorization schemes.

4

Validation Rules

Implemented validation rules to prevent new inconsistencies from entering the system, ensuring long-term data quality.

SQL Queries for Data Cleaning

Using SQL queries alongside Airtable's built-in functionalities, I was able to identify and resolve data quality issues:

-- Identify potential duplicate organizations
-- Using fuzzy matching on organization names
WITH normalized_orgs AS (
    SELECT 
        id,
        organization_name,
        LOWER(TRIM(REGEXP_REPLACE(organization_name, '[^a-zA-Z0-9]', '', 'g'))) AS normalized_name,
        country,
        created_at
    FROM organizations
),
duplicate_groups AS (
    SELECT 
        normalized_name,
        COUNT(*) AS duplicate_count,
        ARRAY_AGG(id ORDER BY created_at) AS duplicate_ids
    FROM normalized_orgs
    GROUP BY normalized_name
    HAVING COUNT(*) > 1
)
SELECT 
    o.id,
    o.organization_name,
    o.country,
    d.duplicate_count,
    d.duplicate_ids
FROM organizations o
JOIN normalized_orgs n ON o.id = n.id
JOIN duplicate_groups d ON n.normalized_name = d.normalized_name
ORDER BY d.duplicate_count DESC, o.organization_name;
-- Standardize country names across the database
UPDATE organizations
SET country = CASE 
    WHEN country IN ('USA', 'U.S.A.', 'US', 'United States of America') 
        THEN 'United States'
    WHEN country IN ('UK', 'U.K.', 'Britain', 'Great Britain') 
        THEN 'United Kingdom'
    WHEN country IN ('UAE', 'U.A.E.') 
        THEN 'United Arab Emirates'
    ELSE INITCAP(TRIM(country))
END
WHERE country IS NOT NULL;

-- Add validation constraint for future entries
ALTER TABLE organizations
ADD CONSTRAINT valid_country 
CHECK (country IN (SELECT name FROM valid_countries));

Leveraging Data for Strategic Insights

Cleaning the data was only the first step. The next challenge was turning it into actionable intelligence. I used SQL and Airtable to create queries that allowed us to:

  • Track trends across humanitarian organizations globally
  • Segment partners by region, project type, and engagement level
  • Identify gaps in services or support based on historical data
  • Forecast needs using historical patterns and current indicators

Building Analytical Queries

-- Partner engagement analysis by region and project type
SELECT 
    p.region,
    p.project_type,
    COUNT(DISTINCT p.partner_id) AS total_partners,
    COUNT(DISTINCT CASE WHEN e.engagement_date >= NOW() - INTERVAL '90 days' 
        THEN p.partner_id END) AS active_partners_90d,
    ROUND(
        COUNT(DISTINCT CASE WHEN e.engagement_date >= NOW() - INTERVAL '90 days' 
            THEN p.partner_id END)::NUMERIC / 
        NULLIF(COUNT(DISTINCT p.partner_id), 0) * 100, 
        2
    ) AS engagement_rate_pct,
    AVG(e.engagement_score) AS avg_engagement_score
FROM partners p
LEFT JOIN engagements e ON p.partner_id = e.partner_id
GROUP BY p.region, p.project_type
ORDER BY engagement_rate_pct DESC;
-- Identify service gaps by comparing partner coverage to need indicators
WITH regional_needs AS (
    SELECT 
        region,
        SUM(population_affected) AS total_affected,
        SUM(funding_requested) AS total_funding_needed
    FROM humanitarian_needs
    WHERE reporting_year = EXTRACT(YEAR FROM NOW())
    GROUP BY region
),
regional_coverage AS (
    SELECT 
        p.region,
        COUNT(DISTINCT p.partner_id) AS active_partners,
        SUM(pr.funding_allocated) AS total_funding_allocated
    FROM partners p
    JOIN projects pr ON p.partner_id = pr.lead_partner_id
    WHERE pr.status = 'active'
    GROUP BY p.region
)
SELECT 
    n.region,
    n.total_affected,
    COALESCE(c.active_partners, 0) AS active_partners,
    n.total_funding_needed,
    COALESCE(c.total_funding_allocated, 0) AS funding_allocated,
    ROUND(
        (n.total_funding_needed - COALESCE(c.total_funding_allocated, 0)) / 
        NULLIF(n.total_funding_needed, 0) * 100, 
        2
    ) AS funding_gap_pct
FROM regional_needs n
LEFT JOIN regional_coverage c ON n.region = c.region
WHERE n.total_funding_needed > COALESCE(c.total_funding_allocated, 0)
ORDER BY funding_gap_pct DESC;

Lessons Learned

My experience at Humanitarian Outcomes taught me several key lessons that are applicable not only to the humanitarian sector but also to any data-driven partnership or business development role:

  1. Clean data is the foundation of action: Without accurate and structured data, no analysis or decision-making process is reliable. Investing in data quality pays dividends across every downstream activity.
  2. Automation saves time and reduces errors: Even small database optimizations and validation rules can have a huge impact on efficiency. What takes hours manually can often be automated in minutes.
  3. Visual insights drive adoption: Presenting data in an accessible and compelling way encourages stakeholders to act on insights. A well-designed dashboard is worth a thousand spreadsheets.
  4. Collaboration amplifies impact: Working closely with team leads, partners, and field officers ensures that database improvements directly translate to better outcomes. Technical work must serve operational needs.
  5. Quantifiable metrics matter: Measuring impact—whether it's a 25% efficiency increase or the number of leads qualified—helps demonstrate value and guide future improvements.
